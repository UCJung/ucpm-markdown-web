## 2. 배경 및 목적

- 해결하려는 문제: Markdown을 편집 문서로 변환하고 다시 저장할 때 지원 문법의 의미와 미지원 블록의 원문을 보존한다.
- 이해관계자: 라이브러리 소비자, Markdown 문서 작성자, 후속 편집 경험·어댑터 REQ 개발자.
- 기존 시스템/프로세스 관계: `REQ-2026-09-0002`의 core schema와 확장 API를 사용하며, MVP 로드맵의 단계 2를 수행한다.

## 3. 범위

### In-Scope

- 기본 Markdown 블록과 인라인 문법을 편집 문서로 import하고 Markdown으로 export한다.
- GFM 표, 체크리스트, 취소선, 자동 링크를 import하고 export한다.
- 지원 문법의 `Markdown → 문서 → Markdown` 변환 의미 보존 fixture를 제공한다.
- raw HTML과 미지원 블록 문법을 실행하지 않고 raw Markdown block으로 import하고 export한다.
- 직렬화 정규화 규칙과 raw 원문 보존 규칙을 fixture 계약으로 명시한다.

### Out-of-Scope

- HTML을 DOM으로 렌더링하거나 실행하는 기능.
- HTML 붙여넣기 변환, 입력 규칙, 목록·표·코드 블록 편집 명령.
- DOM 어댑터, playground, React·Vue 어댑터.
- 이미지 업로드, 수식, Mermaid, 멘션, 콜아웃의 시각 편집 기능.

## 6. 제약조건

- CON-01: Markdown은 공식 입출력 형식으로 유지한다.
- CON-02: 편집 중에는 `REQ-2026-09-0002`의 구조화된 문서 모델을 사용한다.
- CON-03: GFM을 시각 편집 지원 범위의 기준으로 사용한다.
- CON-04: raw HTML과 미지원 블록은 실행하지 않고 원문으로 보존한다.
- CON-05: 문자열 완전 일치가 아닌 지원 문법의 의미 보존을 기본 검증 기준으로 사용한다.

## 7. 가정사항

- ASM-01: 기본 Markdown 문법은 MVP 로드맵에 열거된 문단, 제목, 인용문, 구분선, 목록, 코드 블록과 인라인 문법을 포함한다. [합의 완료]
- ASM-02: raw 보존 fixture는 raw HTML block과 지원하지 않는 블록 문법을 포함해 보존 계약을 구체화한다. [확인 필요]
- ASM-03: raw 보존 블록의 시각 편집 UX는 현재 REQ 범위에 포함하지 않는다. [합의 완료]

| 정규화 | 공백, 목록 기호, 인용문 표기처럼 허용된 직렬화 형식 차이를 일관되게 출력하는 것 |
